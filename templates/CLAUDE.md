# Agent 工作手册（本工程接入 Atlas 治理）

> 本文件同时供 **Claude Code**（读 `CLAUDE.md`）与 **Codex**（读 `AGENTS.md`，软链到本文件）。
> 单一信息源——只编辑 `CLAUDE.md`。

本工程用 **Atlas** 做工程治理。一句话内核：

> **控制点在你（Agent）外面。状态由事实（测试 / 真实 diff）驱动，不由你宣布。**
> 共享的 / 别人依赖的 / 撤不回的东西，碰之前先停下来声明。

完整设计见 Atlas 仓库 `docs/`。下面是你每次干活必须遵守的最小流程。

---

## 每个 feature 的工作流

1. **开工先 register（声明范围 = 基准线）**
   ```bash
   atlas register --feature <id> --files <你打算碰的文件,逗号分隔> --acceptance "验收标准"
   ```
   这条范围是**硬锚**，是后面判定你有没有越界的基准。你能自己定的是"怎么做"，不是"做到哪"。

2. **在范围内自由实现**。怎么写、分几步，你说了算。

3. **共享接口走契约，别直接改公共模块**
   - 依赖别人的基础模块时，对**契约**编程，先用占位符顶替。
   - 契约登记进看板（住看板，不住对话），做成**可执行的契约测试**。
   - 占位符替换的扳机是**契约测试通过这个事实**，不是谁说"我做好了"：
     ```bash
     atlas contract run --id <cid> --cmd "<跑契约测试的命令>" --feature <id>
     ```
   - **你不能单方面改契约**。发现契约不合理 → 停下来，把"需要改成 X"抛回去让人确认。

4. **收工交事实**
   ```bash
   atlas submit --feature <id>     # 抓真实 git diff 交服务端机械比对（也可由 Stop hook 自动做）
   ```
   服务端比对"声称/承诺 vs 实际"，越界自动标红。**你写得越多，对照面越大，越藏不住。**

---

## 越界处置（判据是"能不能撤"，不是"风险多大"）

- **可逆 · 局部**：可以做，但**必须显式声明**（标明越界、动了什么、为什么）。
- **撤不回 · 全局**（公共契约 / 跨模块依赖 / 数据结构）：**撞线必停**，退回人确认，不要自作主张。
- **没有"默默越界"这个选项**——要么停，要么声明。

发现超出当前 feature 范围的事 → **吐到看板成为下一轮输入**，不要当场吞进当前 feature。

---

## 给机器记的，别自己背

能被 lint / 类型 / CI / hook 卡死的规则，不写在这里——机器替你挡，你撞墙了自然知道。
这里只放机器强制不了的品味与流程。

## 去哪找什么

- 服务端地址 / projectId：`atlas.config.json`
- 全局看板（所有人/Agent 的事实状态）：`atlas board` 或浏览器打开服务端首页
- 设计原理（为什么是事实驱动）：Atlas 仓库 `docs/`
