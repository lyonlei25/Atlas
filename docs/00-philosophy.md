# 00 · 设计哲学

> 为什么这套方案不是「加测试 + 加文档 + 加 code review」？
> 因为那些没有 Agent 也成立。Agent 带来的是人类工程方法论里压根没遇到过的新问题。

---

## 一、唯一不可绕过的硬约束

> **Agent 的产出能力 ≫ 人类的验证能力，而信任只能靠验证建立。**

项目小的时候没事，因为你看得过来。项目一大，它产出的量远超你能读的量，于是越来越多没人真正看过的代码进了系统。**失控不是某一天突然发生的，是「没看过的代码」占比一点点变高，高到出了问题没人知道是哪来的。**

这条鸿沟是物理事实，**不会随模型变强而消失，反而会变宽** —— 模型越强产出越多，人的脑子没变快。

所以工程治理的目标不是「让 Agent 不犯错」（做不到），而是：

> **用最少的人类验证，换取最多的系统可信度。**

一切手段都是这个优化问题的解。

---

## 二、根因：Agent 没有「自我怀疑」

人类工程师身上有一种隐式的刹车：

- 读到一份文档会想「这是不是旧了」
- 测试绿了会想「我是不是测错了地方」
- 写完一坨代码会有「这里我心虚」的感觉

这种不舒服感是品味和经验的副产品，它让人在该停的地方停下来。**Agent 没有。** 它对过时文档、对绿色的假测试、对自己刚生成的几千行，抱有完全一致的、毫无波动的自信。

几个看似不同的痛点，其实是同一个缺失在不同层面的投影：

| 现象 | 本质 |
|------|------|
| 反复犯同样的错、推翻定过的决策 | 没有跨 session 记忆 |
| 为了让测试变绿，去改测试而不是改代码 | 优化代理指标，而非真正的目标 |
| 几千行没人读得完的代码进了主干 | 产出速度 ≫ 理解速度 |
| 多个 Agent 各自改得都对，合起来不一致 | 意图分裂，且都看不见彼此 |

它们底下是同一句话：**它不会在该不确定的地方不确定。**

---

## 三、一个致命的死循环（必须避开）

很自然会想到：那就让 Agent「标注哪里没底」「先说计划」「暴露过程」不就行了？

**不行。** 这些都要求黑盒自己汇报自己，而黑盒的汇报跟黑盒的产出一样不可信：

> 你没法用「问黑盒」来解决「黑盒不可信」。这是拿病去治病。

你让它标注信心，它就真给你一个真实的信心吗？它说「这里我有把握」，你凭什么信这个「有把握」本身不是它编的？

**结论很冷但很实在：**

> 你能控制的东西，从来不在 Agent 内部，只在它的外面。

任何「让它告诉你……」的招，本质都是求它配合，而你管不了它配不配合。真正能落地的，只剩那些**不需要它配合、它骗不了的东西**。

---

## 四、三类「它骗不了」的控制点

这是整套方案的支点。面对黑盒，凡是「让它……」的都是空的；凡是「在它外面卡住……」的才是实的。

### ① 它的产出能不能跑、对不对 —— 它没法演

它可以说一百遍「我有把握」，但代码跑起来错了就是错了，这个不看它的嘴。给它一个它改不动的现实去撞（真实数据、真实调用、真实环境），它在「假装能跑」和「真的能跑」之间没有中间地带可以骗你。

### ② 它能碰到什么、碰不到什么 —— 你说了算

你管不住它的脑子，但管得住给它什么权限、什么工具、什么范围。它碰不到生产数据库，就删不了你的数据，不管它「想」还是「不想」。**这是唯一一类你单方面就能落实、完全不依赖它配合的控制。**

### ③ 出了事能不能快速发现和退回 —— 全在外面

你拦不住它犯错，但它犯错之后，系统能不能十分钟内冒红灯、能不能一键退回上一个好状态 —— 这套跟 Agent 一点关系都没有，它干扰不了。**这才是面对不可信黑盒时真正攥在手里的底牌。**

---

## 五、关于「约束」的一个反直觉修正

直觉上「加约束 = 多份安全」。但：

> 约束对**人**是减负（规则越清楚越不用动脑）；
> 对 **Agent** 可能是加负 —— 它每次把上下文整个读进去，每条规则都在占它的注意力。

人能把规则内化成习惯然后忘掉，**Agent 没法忘，每条都得现场扛着**。规则一多，它反而抓不住重点，甚至为了同时满足一堆约束写出更扭曲的代码。

所以方向不是「少约束」，而是：

> **能交给机器强制的，就从 Agent 的脑子里拿走** —— 让机器替它记着，它撞墙了自然知道。

这条原则贯穿后面所有层（详见 [01](#l1)）。

## 六、不透明的两个面，是同一个病

| 面 | 体感 | 根 |
|----|------|-----|
| 干的时候不知道它在干嘛 | 等它交了才发现跑偏 | 它干活时不暴露犹豫 |
| 交了之后看不出该信多少 | 只能要么全信、要么全部重看 | 它交活时不标注信心 |

两者都是「它把『自己有多大把握』这个信息全程藏住了」。**而且很大一部分不透明不是 Agent 的属性，是「长回合」工作方式的属性** —— 你让任何人关进小黑屋三小时再交东西，他也是黑盒。

这给了一个方向（落在 [03](#l3)）：**不是想办法看穿黑盒，是把回合切短，让它根本来不及变成黑盒。**

---

## 小结

```
能力 ≫ 验证（硬约束）
   └─ 因为 Agent 没有自我怀疑（根因）
        └─ 所以别让它自我汇报（死循环）
             └─ 控制点全部移到外面（支点）
                  └─ 三类骗不了的控制：能否跑 / 能否碰 / 能否退回
```

后面五份文档，都是这套哲学在不同尺度上的具体落法。
