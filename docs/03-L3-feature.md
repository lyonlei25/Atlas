# 03 · L3 Feature 级治理

> **时间尺度**：短期，一个 session 内。
> **防的是**：引入外来问题。
> **核心手段**：硬锚 + 软实现；全程用事实审，不靠自陈。

这是唯一一层「黑盒不可控」真正咬人的地方 —— 前两层人还能主导（规则人定、范围人冻），到这层才是 Agent 自己在 session 里跑。

---

## 两层锚：一硬一软，各管各的

| | 范围 | 执行细节 |
|---|------|---------|
| **是什么** | feature 边界、碰哪些模块、验收标准 | 具体怎么实现、用什么结构、分几步 |
| **谁定** | L2 拆 feature 时焊死 | session 里 Agent 自己评估 |
| **能不能改** | 硬锚，Agent 改不动 | 软，Agent 的自由地盘 |
| **作用** | 越界与否的判定基准 | 给它干活空间 |

> 它能自己定的是**怎么做**，不是**做到哪**。
> 「做到哪」那条线归上层、它改不动，所以拿它当比对基准是硬的。

---

## 两个诉求，难度天差地别

**「快速精准完成需求」—— 相对好办。**
范围已被焊死，Agent 在小盒子里干活，给足上下文（要什么、碰哪些文件、验收标准），完成得不会差。前两层做好了，这层的「完成」水到渠成。

**「不引入外来问题」—— 这才是硬骨头，也是黑盒最咬人处。**

> 「完成需求」是看得见的（功能跑通了）；
> 「引入了外来问题」是看不见的 —— 它为了让这个 feature 跑通，顺手 mock 了什么、catch 了什么异常、改了某个公共函数导致别处坏了、加了个「临时」绕过。

这些都不在它交给你的「我完成了」里。**它报喜的部分是真的，它惹的祸藏在你看不到的地方。**

---

## Session 全流程：Agent 只做两件没法造假的事

![feature session 时序](03-feature-session.svg)

Agent 全程只做两件它没法造假的事：**立锚 + 交 diff**。所有「判断」都在它外面、用事实做。

1. **注册** —— 声明范围 + 验收（接受上层硬锚），看板登记基准线。
2. **评估执行细节** —— 怎么实现，归 Agent，自由。
3. **干活**。
4. **交实际 diff（原样）** —— 骗不了的事实。
5. **机械比对（不让 Agent 自审）** —— 看板侧做，见下。
6. **状态翻牌 = 测试 / CI 通过** —— 不是 Agent 说「完成」就翻。

---

## 比对：要比两个差，别只盯一个

看板侧用 diff 机械地比，抓两类不同的问题：

| 比对 | 抓什么 |
|------|--------|
| **声称改的 vs 实际改的** | 它**藏起来**的越界（说没碰，其实碰了） |
| **当初承诺的范围 vs 实际改的** | 它的**范围蔓延**（一开始没说要碰，后来自作主张碰了） |

> 这两个不一样。前者是它瞒，后者是它擅自扩张。
> L2 最担心的「Agent 中途自己扩大范围」，恰恰靠后一个差才抓得住。

**最容易做歪的一点 ——**

> 比对这个动作，**必须是看板侧用 diff 做的**，不能是 Agent 在 session 里自己比完、自己写个「我没越界」上去。
> 否则又绕回「黑盒汇报自己」：它会真心觉得自己没越界（它没有自我怀疑），写个「范围一致」上去，你就瞎了。

审的人和被审的人不能是同一个黑盒。Agent 负责**提交原材料**，看板负责**审判**，两个角色不能一肩挑。

---

## 越界处置：判据是「可逆 / 撤不回」

「执行细节在 session 里评估」会必然撞上一个接缝：**评估结论可能要顶破范围。**

> 它评估具体怎么实现，评着评着发现绕不开去动一个范围外的东西。
> 它不是恶意越界，是真心觉得「不这么改这 feature 做不完」 —— 于是顺手就改了，还觉得理所当然。
> **「引入外来问题」十有八九就是从这条缝进来的。**

处置不能一刀切，判据是**能不能撤**（客观），不是**风险多大**（主观）：

![越界处置](03-overstep.svg)

| 越界碰的东西 | 处置 | 兜底 |
|------------|------|------|
| **可逆 · 局部小事** | 允许做，但**必须显式声明**（标明越界、动了什么、为什么） | 就算不声明，diff 比对照样露馅 |
| **撤不回 · 全局大事**（公共契约、跨模块依赖、数据结构） | **撞线必停**，退回人确认（重焊范围 / 驳回） | 碰这类东西即触发停，由流程拦，不靠它自觉 |

> **没有「默默越界」这个选项** —— 要么停，要么声明，两条路都通向暴露。
> 两道防线都不靠 Agent 的良心：前面流程拦，后面 diff 抓。

---

## 关于「切短回合」

回想 [00](#philosophy)：很大一部分不透明是「长回合」养出来的。L3 内部也用这个思路：

- **对付「干的时候不知道在干嘛」**：干之前先说打算怎么干（几句话），瞄一眼方向对了再放它走。把「三小时后才发现跑偏」变成「开头三十秒就拦住」。
- 它一次干得越少、越频繁浮上来对一下，过程就越不黑 —— 不是因为你看穿了它，是**没给它攒出黑盒的时间**。

> **什么活该切多碎，是你作为管项目的人真正要拿捏的手艺**：
> 改个小 bug 可以让它一把梭；动核心结构就得切得很碎。

---

## 一句话

> L3 让 Agent 在硬范围里自由实现，但它没法「神不知鬼不觉地改范围外的东西」：
> 撞撤不回的线就停，碰可逆的越界必声明，而 diff 比对在最后兜底抓它没说的部分。
