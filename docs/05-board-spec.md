# 05 · 看板规格：分层可信的共享现实

> **解决的是**：共享知识库会烂成「自信的谎言纪念碑」。
> **核心手段**：三级可信度 —— 让事实托底，把会撒谎的纯文字隔离、标记、贬值。

---

## 看板的真实定位

它不是「AI 时代的 TAPD」，它是：

> **给一群健忘的、互相不透明的黑盒，装一个共享的外部大脑。**

- 单个 Agent 每个 session 失忆 → 看板帮它记着项目到现在为止发生了什么。
- 多个 Agent 互相是黑盒 → 看板让 A 的 Agent 读到 B 的 Agent 留下的东西。

前面那些「黑盒攒不出共识」「理解会分叉」的问题，这个看板从结构上接住。

---

## 致命陷阱：公共知识库会烂，且烂法跟黑盒同病

> 库里存的契约、设计理由、「这块怎么用」**会过期**。然后下一个 Agent 来读这个库 —— 它**完全信任**这个库（这正是你建库的目的），读到一条过期的东西，自信地照着干，坏了。

**这就是「文档会撒谎」，只不过现在这个会撒谎的文档是全团队所有 Agent 共享的权威。**

> 公共知识库的可怕之处恰恰在于它的「公共」：它对了所有人受益；它错了所有人一起错，而且错得理直气壮，因为它是「权威」。

所以真正的难点不是「建库让 Agent 写和读」（容易），而是：**怎么让这个库不烂？**

> 答案不是「有人勤快维护」，是**结构本身让「会过期的东西」没法伪装成「永远正确的东西」。**

---

## 解法：三级可信度

![看板三级可信度](05-board-tiers.svg)

库里的东西分三层，**拼命扩大前两层、死死盯住第三层**。一个 Agent 来读，必须能分清自己读到的是哪一层。

### 骨架结构

```
Project
 └─ Milestone（里程碑）
     └─ Feature 列表
     └─ 接口契约
```

### ① 事实层 —— 无条件可信，Agent 改不动

- **数据来源**：实际 diff、测试结果、CI 状态、操作痕迹
- **承载**：feature 状态流转（由测试驱动翻牌）、改了哪些文件、声称 vs 实际的比对结果
- **关键**：这层不靠 Agent「描述」，**直接从它的操作自动抽取**（比如直接从 git diff 拿）→ 它想美化也美化不了

> 它说「我只动了登录模块」，但 diff 里它还改了支付模块 —— 这个谎当场就穿。
> 凡是能从实际操作里自动抽出来的，就别让它「描述」，直接抽。

### ② 契约层 —— 高可信，有测试兜底

- **承载**：模块对外接口契约，做成「可执行」而非纯文字
- **机制**：契约一旦与实现裂开 → 测试报红 → 立刻暴露
- **关键**：往「可执行」拼命拉（详见 [04](#modules)）

### ③ 说法层 —— 仅参考，必然漂移

- **承载**：wiki 里的设计理由、经验、踩坑提示（机器验证不了）
- **约束**：
  1. 必须挂**出处 + 时间**（对应哪次开发、哪份 diff、何时写的）
  2. 当**线索**不当真理
  3. **旧的自动贬低可信度**（三个月前的设计随笔在高频演化的模块上很可能已不准）
- **关键**：**会传染！** A 写歪 → B 当真、基于它干活、写一条更歪的 → C 再读……错误理解会在库里发酵、放大

> 这正是「理解分叉」被看板固化下来、还到处传。
> 压制办法：每条说法必须可溯源到对应 diff。**连不回任何事实的说法 = 最低可信度的传言，不是定论。**

---

## 三层绝不能混成一锅

> 一个 Agent 来读，绝不能把一条三个月前的过期设计随笔，当成跟「契约测试刚通过」同等权威的东西去信。

| 读到 | 怎么用 |
|------|--------|
| 事实层 | 放心用 |
| 契约层 | 基本可信（有测试兜底） |
| 说法层 | 带着怀疑用，回去对照现状 |

那样这个公共知识库就不是大脑，是**会传染错误记忆的瘟疫源**。

---

## Skill 该往看板交什么

每个参与者的 Agent 装一个 skill，在参与各层开发时把信息汇总到看板。关键在于**分清哪些 Agent 说了算、哪些事实说了算**：

| 信息 | 谁说了算 | 怎么交 |
|------|---------|--------|
| feature 状态流转 | 事实（测试/CI） | 自动翻牌，不是 Agent 宣布「完成」就翻 |
| 改了什么 | 事实（diff） | **skill 把 session 的实际 diff 原样交上去** |
| 声称 vs 实际的差 | 事实（机械比对） | 看板侧用 diff 比，对不上就标红提醒人 |
| 为什么这么实现 / 经验 | Agent（说法） | 进 wiki，但标明是说法、挂出处时间 |

> **核心前提**：skill 必须能拿到 Agent 的**实际操作痕迹**（最直接是 git diff）。
> 有了它，「用事实揭穿自陈」才能跑：它写得越多，对照面越大，越藏不住。
> **它的自陈从「你要信的东西」变成「你用来抓它的东西」。**

---

## Diff 要「开工交一次、收工交一次」

只在完成时交一次 diff，你拿到的是终态，看不到过程，而且**越界已经发生了你才知道**。

- **注册时**：声明「打算碰哪些文件、做到什么验收」（承诺，也是比对基准线）
- **完成时**：交实际 diff，跟当初承诺比

> 没有开工的承诺，收工的 diff 就没有参照物 —— 你只知道它改了啥，不知道它是不是越界了。
> **越界 = 实际改动超出了它自己当初声明的范围**，这条线必须它先划下、划完就锁死，才有意义。

---

## 一句话

> 看板不烂的秘密不是有人维护，是它的结构让「会过期的说法」没法冒充「永远正确的事实」：
> 事实层自动抽取、契约层测试兜底、说法层挂源贬值 —— 三层泾渭分明。
